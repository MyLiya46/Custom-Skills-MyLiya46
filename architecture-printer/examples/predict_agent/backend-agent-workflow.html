predict_agent · 后端端到端工作流

一次请求经过哪些阶段？

从前端提交 ChatRequest 开始，经过 API 接入、规划决策、确定性工具执行，写入会话与业务表，最后以 ChatResponse 把 text → chart → table 交给前端。点击任一节点，从概览下钻到精确契约。

接入 / 编排规划 / 决策执行 / 工具适配 / 网关持久化外部边界实线：主链路　虚线：分支 / 黑盒
数字边界：销量数字只能来自本地预测模型的 Excel 输出；规划器、Turing、Agent Chat API 等 LLM 生成路径不得编造销量数字。页面示例均为 ※ 示意数据，非真实销量。

预测工具 · 输入 / 输出契约 （D 节 · 黑盒）

输入：只提交品类 + 预测基准月

ForecastModelClient.ensure_run(
  category, forecast_month,
  *, wait=True, force_refresh=False)
→ POST /predict
{ systemForecastNumber, productLine,
  reporter, forecastMonth: "YYYY-MM-01",
  categoryBatchMappingDTOList: [
   { category, priceBatchNumber,
     productBatchNumber } ] }
→ GET /tasks/{task_id}

ExcelResultAdapter(output_path)
.extract_forecast(category, channel, sku,
  series, start, end, horizon)
.extract_attribution(..., top_k=15)

品类 → 批次号：FORECAST_CATEGORY_BATCH_MAP_JSON；渠道 / 型号 / 系列仅在 Excel 侧筛选，不触发重跑。
