# Plan 文件模板与命名规范

计划文件默认存放于 `docs/plans/`，**一任务一文件，互不重名**。

## 命名规范

```
{T{n}-}description-of-the-plan-YYYY-MM-DD.md
```

| 部分 | 说明 |
|---|---|
| `T{n}` | 任务 ID 前缀（如 `T01`），与 todo 清单「任务 ID」列一一对应 |
| `description-of-the-plan` | 英文短名，kebab-case，与 todo「标题（英文短名）」列一致 |
| `YYYY-MM-DD` | 创建日期（当天） |

## 字段结构

每份计划文件固定包含：标题、元数据块、实施要点、验收标准、状态。

```markdown
# T{n} · 标题（英文短名）

- **任务 ID**：T{n}
- **标题与目标**：（一句话，说清本任务交付什么、可验证结果）
- **关联文档章节**：（PRD / 技术设计 §X.X，可多条）
- **前置依赖 blockedBy**：（`无` | `T{n}、T{n}`，与 todo 表 blockedBy 严格一致）

## 实施要点

### 1. （步骤标题）
（落到「对象 + 动作 + 参数值」的具体步骤，允许贴代码块 / 目录树）

### 2. …

## 验收标准
- [ ] （每条含至少 1 条**可运行验证项**：`pytest …` / `npm run build` / `curl …`，不写口号式描述）

```

## 写作红线

- 每条实施步骤必须落到「对象 + 动作 + 参数值」。
- 禁止出现「待定 / TBD / 等用户 XX / 占位 / 后续再定」等字眼。
- 参数无法确定时：不写占位，改为「列疑点向用户确认」，并在该处显式标【假设】。
- 验收标准每条要「可运行验证」，禁止「功能可用 / 体验优化」一类口号。
