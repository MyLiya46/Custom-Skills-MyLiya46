# Plan 文件模板与命名规范

计划文件默认存放于 docs/plans/，一任务一文件，互不重名。

## 命名规范

T{n}-description-of-the-plan-YYYY-MM-DD.md

## 字段结构

计划文件保存执行详情，不保存生命周期状态；生命周期状态统一写在 docs/todo.md。

示例结构：

    # T{n} · 标题（英文短名）

    - 任务 ID：T{n}
    - 标题与目标：（一句话说明可验证交付物）
    - 关联文档章节：（PRD / 技术设计章节）
    - 前置依赖 blockedBy：（无 | T{n}、T{n}，与 todo 严格一致）

    ## 实施要点

    ### 1. （步骤标题）
    （落到“对象 + 动作 + 参数值”的具体步骤）

    ## 验收标准
    - [ ] （可运行验证项，例如 pytest、npm run build 或 curl）

## 写作规则

- 每条步骤必须落到“对象 + 动作 + 参数值”。
- 涉及文件直接写在步骤中；只有需要给 executor 明确白名单时才额外列出文件清单，避免重复复制路径。
- 跨任务共享的口径直接保留在 todo 的关键口径部分，不新增独立决策文件。
- 可保留具体的【假设：...】，但不得把“占位、待定、待确认”当作参数值。
- 验收标准必须能直接运行或由明确命令验证，禁止只写“功能可用”“体验良好”。
- plan 评审通过后只更新 docs/todo.md 的状态；旧 plan 中已有的“状态”字段不主动删除或重写。
