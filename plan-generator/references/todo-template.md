# Todo 清单模板与格式规范

任务清单默认写 `docs/todo.md`，固定「元信息 + 三段结构」。

> **首写模式** 从零生成整份清单。默认路径为 `docs/todo.md` 。
> **续写模式** 目录已有 `docs/todo.md` 。不重写整份清单，只做追加——新任务接在现有最大号之后、blockedBy 可跨代引用既有任务、拓扑注释只新增本次条目、交付物核对只核本次新增项、历史任务行原样不动。
> 
## 元信息（文件头）

```markdown
# （项目名）· 实施任务清单

> 日期：YYYY-MM-DD
> 计划文件目录：docs/plans/
> 说明：本清单与 docs/plans/ 下任务计划一一对应（一任务一文件），以拓扑顺序排列（前置任务在前）。
```

## 一、任务总览（拓扑顺序 = 建议执行顺序）

每行一个任务，字段对齐：

```markdown
| 序号 | 任务 ID | 标题（英文短名） | blockedBy | 状态 | 验收要点（摘要） | 计划文件 |
|---|---|---|---|---|---|---|
| 1 | T01 | 初始化（project-scaffold） | 无 | **pending** | 摘要，含 1 条可运行验证点 | [project-scaffold-YYYY-MM-DD.md](plans/T01-project-scaffold-YYYY-MM-DD.md) |
```

字段约定：
- **任务 ID / 标题英文短名 / 计划文件名**三者一一对应、互不重名。
- **blockedBy**：`无` 或逗号分隔的任务 ID 列表，须与「二、拓扑顺序注释」一致、整体无环。
- **状态**：语义与流转见 SKILL.md「任务状态」——`pending`（待评审，拆解默认）/ `reviewed`（已评审可开工）/ `completed`（已完成）/ `blocked`（阻塞）。评审通过 = 由 `pending` → `reviewed`，执行完成 由 `reviewd` → `completed`。

## 二、拓扑顺序注释（blockedBy 依据摘要）

分段说明依赖关系，保证单向无环（DAG）；可并发的任务明确写出「可并行」。必须与上表 blockedBy 严格一致，无遗漏、无环。

```markdown
- **（层 / 支名称，日期，据 XX 源方案）**：任务简述……拓扑：
  - `T01` 无前置；`T02` 依赖 `T01`；
  - 「关键口径」以硬约束列出（单一事实来源 / 零回归 / 分派规则等）。
  - 【假设】显式保留（近似口径、命名、阈值等）。
```

## 三、交付物核对（对照任务要求）

```markdown
- [x] docs/plans/ 下生成计划文件，文件名符合 `T{n}-description-YYYY-MM-DD.md`，互不重名
- [x] 任一计划文件可独立开工（含 blockedBy/步骤/涉及文件/可运行验收项）
- [x] todo.md 按拓扑顺序列出全部任务，字段完整，状态正确
- [x] 每任务验收标准至少含 1 条可运行验证项
- [x] 本次新增计划已逐条评审通过，无占位 / 待定字眼
```

> 首次 / 续写 / 覆盖重拆的判定与规则见 SKILL.md「使用模式」。
