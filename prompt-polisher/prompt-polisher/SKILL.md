# prompt-polisher · 需求提示词打磨器

## 目标

把「模糊、不专业、考虑不周全」的原始描述，转化为**清晰、专业、完整、可验证**的提示词（prompt），提高人与 AI 的沟通效率，降低反复修改需求的成本。

典型痛点：

| 痛点 | 例子 |
|---|---|
| 模糊词泛滥 | "优化一下""好一点""尽量""尽快" |
| 目标不清 | 不说明给谁用、解决什么问题 |
| 关键维度缺失 | 无输出格式、无约束、无验收标准、无边界情况 |
| 隐式假设 | 心里有想法但没说，AI 只能猜方向 |

## 工作流程

### 第 1 步 · 解析输入

通读原始描述，提取已有信息：

- **目标**：用户最终要达成什么
- **对象**：对什么做、给谁做（目标用户 / 受众）
- **场景**：在什么环境、什么上下文下使用
- **已明确**：已有的约束、偏好、禁止事项

### 第 2 步 · 差距分析

对照下方「完整性检查清单」逐项标记：✅ 明确 / ⚠️ 模糊 / ❌ 缺失。

选出**影响最大的 2-4 个缺口**——判定标准：这个缺口若被猜错，是否会导致方向性错误或返工。

> 若绝大多数维度已明确（输入本身已较专业），跳过提问，直接输出轻量增强版，并附简短设计说明。

### 第 3 步 · 澄清提问

- 用 `AskUserQuestion` 工具提问，**最多 4 题**，每题 2-4 个互斥选项
- 选项措辞要具体、可直接选用；有推荐方案时放第一位并标注 `（推荐）`
- 未提问的缺口：采用**合理默认假设**，在最终输出中显式标注为【假设】

### 第 4 步 · 综合优化

按下方「标准输出结构」撰写最终提示词：

- **语言跟随用户输入语言**（用户用中文 → 中文输出；英文 → 英文输出）
- 用具体、可验证的表达替换模糊词（对照表见 `references/prompt-engineering-principles.md`）
- 把隐式假设显式化；禁止事项明确列出
- 提示词末尾附「设计说明」：3-5 条，说明关键设计决策、默认假设、哪些部分可按需替换

### 第 5 步 · 交付

- 以代码块给出**可直接复制**的最终提示词
- 附 1-2 句使用提示：可直接粘贴使用；提示词已内置"遇到歧义先确认"的交互约定

## 完整性检查清单

差距分析的标准，也用于设计最终提示词的内容：

1. **目标 Goal** — 一句话能说清最终要什么吗？目标可验证吗？
2. **角色 Role** — 需要 AI 以什么身份 / 专业视角执行？（如：资深架构师、前端专家）
3. **背景 Context** — 为什么做？现有条件、技术栈、相关历史决策？
4. **输入 Input** — AI 需要哪些输入？格式、来源、范围？
5. **任务 Task** — 指令是否动词明确？大任务是否拆分步骤、给出执行顺序？
6. **输出 Output** — 交付物形态、格式、语言、篇幅、结构？
7. **约束 Constraints** — 技术栈 / 平台 / 预算 / 时间 / 合规 / 资源限制？
8. **质量 Quality** — 是否有可量化标准？（准确率、覆盖率、性能、风格）
9. **边界 Edge cases** — 极端输入、异常数据、部分失败时如何处理？
10. **禁止 Negative** — 明确"不要做什么"？
11. **验收 Acceptance** — 完成后如何验证？可检查项？
12. **示例 Examples** — 有无期望行为样例（few-shot）？
13. **交互 Interaction** — 允许 AI 追问吗？可迭代几轮？

## 标准输出结构

最终提示词的推荐结构（缺失项需给出【假设】，无需的章节可裁剪）：

```
# 角色
（可选）你是一位资深的……，精通……

# 背景
（为什么做这件事、现有条件、相关上下文——只保留与任务有关的信息）

# 目标
（一句话核心目标；如有多个子目标用列表，并标注优先级）

# 输入
（输入内容 / 数据 / 参数说明；来源与格式）

# 任务
（动词开头的行动指令；复杂任务给出执行顺序）

# 输出要求
- 格式：……
- 语言：……
- 篇幅：……

# 质量要求
（可量化的标准，例如：错误率 < 1%；覆盖全部 X 类场景；符合 Y 规范）

# 约束条件
- 技术栈 / 平台 / 资源 / 时间 / 合规……

# 边界与异常处理
- 遇到 A 情况 → 按 B 方式处理
- 信息不足 → 先列出缺失项并提问，不要擅自假设

# 禁止事项
- 不要……

# 验收标准
- [ ] 可检查的完成标准（逐条列出）

# 示例
（可选）输入：…… → 期望输出：……

# 交互约定
- 执行前如发现歧义，先向用户确认，不要擅自决定
- 输出后欢迎用户提出修改意见，最多迭代 N 轮
```

## 质量红线

输出提示词时不得出现以下特征：

- ❌ 模糊词残留：优化 / 完善 / 好一点 / 尽量 / 大概 / 尽快（除非无法量化，且注明原因）
- ❌ 目标与任务分离不清，用户无法判断 AI 该做什么
- ❌ 多个主任务并列却无优先级
- ❌ 无验收标准或边界处理，无法判断成败
- ❌ 塞入无关上下文（信息过载稀释注意力）
- ❌ 默认 AI 能猜到用户的想法——一切隐式假设必须显式化
