# 提示词工程前沿规范速查

> 来源：Anthropic Prompt Engineering 官方文档、OpenAI Prompt Engineering Guide、社区最佳实践（截至 2026 年的共识）。

## 核心原则（优化时逐条对照）

1. **清晰直接（Be clear and direct）** — 用最直白的语言说清要求，避免文学化修饰。写不明确，删；写不直接，改。
2. **具体代替模糊（Specificity）** — "好一点"没有信息量。给出数字、枚举、示例。模糊表达见下方替换对照表。
3. **把假设显式化（Make assumptions explicit）** — 用户没说的默认值、边界、取舍，全部写成文字。AI 不会读心。
4. **单一任务聚焦（One task at a time）** — 一个提示词一个主任务；多个任务时拆分子步骤并标优先级。
5. **角色设定（Role prompting）** — 给出专业身份（"资深架构师"），激活对应领域的知识组织方式。
6. **少样本示例（Few-shot examples）** — 1-3 个"输入 → 期望输出"示例，往往比长篇文字描述更有效。
7. **结构化指令（Structured instructions）** — 用标题、列表、XML 标签分段，降低解析歧义。API 场景推荐 XML 标签包裹各区块。
8. **让模型思考（Give the model room to think / CoT）** — 复杂任务让模型先拆解计划、逐步推理，再输出结论。
9. **负面约束（Negative constraints）** — 明确"不要做什么"，防止模型自作聪明。
10. **边界与异常（Edge cases）** — 极端输入、数据缺失、部分失败的处理策略，必须在提示词里约定。
11. **可验证的验收标准（Verifiable acceptance criteria）** — 每条标准可被检查："界面好看"不可验收，"错误率 < 1%"可验收。
12. **结构化输出（Structured output）** — 需要机器消费时指定 JSON Schema 或明确字段清单。
13. **交互契约（Ask-when-ambiguous）** — 在提示词中授权模型"遇到歧义先提问"，而不是猜测。这是降低返工率最有效的一条。
14. **上下文精简（Relevant context only）** — 只放与任务相关的信息；无关背景会稀释指令权重。
15. **基于评估迭代（Iterate with evaluation）** — 用一组测试用例检验提示词效果，迭代而非一次到位。

## 模糊词 → 具体表达对照表

| 模糊表达 | 具体表达 |
|---|---|
| 优化一下 / 好一点 | 明确指标：响应时间 < 200ms、准确率 ≥ 95% |
| 尽快 / 马上 | 明确截止：今天 18:00 前交付初版 |
| 尽量完整 / 覆盖全 | 明确范围：覆盖全部 20 个字段 / X 类场景 |
| 专业一点 | 采用 X 行业术语，遵循 Y 标准 / 规范 |
| 好看 / 美观 | 参考 Z 风格，符合 W 设计规范，主色 #RRGGBB |
| 支持多种格式 | 枚举明确：PDF、Word、Markdown 三种 |
| 功能要全 | 列出功能清单，按 P0 / P1 / P2 排优先级 |
| 处理一下错误 | 明确错误类型与策略：重试 / 降级 / 报错提示 |
| 差不多就行 | 明确容差阈值（如 ±5%） |
| 简单点 | 明确排除清单：不做 X、Y、Z |

## 当代前沿要点（2026 共识）

- **XML 标签 / 结构化分段**辅助模型解析长提示词（API 场景尤佳）
- **Plan-then-execute**：复杂任务先让模型交方案，确认后再动手，避免方向性返工
- **少样本示例优于长篇描述**：同样信息量下，示例更稳定
- **每个需求配验收标准**，最好可自动化检查
- **把"提问权"写进提示词**：AI 遇到歧义应询问而非猜测
- **用测试集评估提示词质量**：改一次提示词跑一遍用例，而不是凭感觉迭代
