# 示例：从模糊需求到专业提示词

## 原始输入（用户原话）

> 帮我做个客户管理系统，要好用一点，功能全一点，最好能管客户信息、订单什么的。

## 差距分析

| 维度 | 状态 | 问题 |
|---|---|---|
| 目标 | ⚠️ | "客户管理系统"范围过大，未定 MVP 边界 |
| 角色 | ❌ | 未指定 AI 身份 |
| 输入 | ❌ | 客户数据从哪来？格式？ |
| 技术栈 | ❌ | 未指定 |
| 输出 | ⚠️ | "功能全"未枚举 |
| 质量 | ❌ | "好用"无可验证标准 |
| 验收 | ❌ | 无 |
| 边界 | ❌ | 无 |
| 交互 | ❌ | 未定 |

## 澄清提问（示例）

1. MVP 优先做哪几块功能？（客户管理 / 客户+订单 / 全功能）
2. 技术栈偏好？（前端 React + 后端 Node + SQLite / 纯前端方案 / 其他）
3. 数据从哪里来？（手工录入 / 从 Excel 迁移）
4. 对"好用"的定义？（操作流畅 + 界面规范 / 功能全面优先）

## 优化后的最终提示词

```
# 角色
你是一位资深的全栈工程师，精通 Web 应用开发、数据库设计与用户体验优化。

# 背景
客户希望搭建一套内部使用的客户管理系统，用于记录客户信息与订单，
替代当前手工维护的 Excel 表格。当前无任何现存系统，数据需从
customers.xlsx 迁移。系统为内部工具，单用户使用，无需登录。

# 目标
交付一个可用的最小可用版本（MVP），支持：
1. 客户信息管理（增删改查）
2. 订单记录与客户关联
3. 客户检索与列表导出

# 输入
- 待迁移数据：customers.xlsx（字段：客户姓名、电话、邮箱、公司、备注）
- 数据量预计 ≤ 1 万条

# 任务
分三步执行：
1. 先给出设计方案（功能清单 + 数据表结构 + 页面清单），我确认后再编码
2. 按确认的方案实现前端页面与后端接口
3. 提供数据迁移脚本并验证导入结果

# 输出要求
- 交付物：可运行的完整代码 + 部署/启动说明 + 数据迁移脚本
- 代码注释与文档使用中文

# 质量要求
- 客户数据导入准确率 100%，非法数据逐条输出报告
- 检索响应时间 < 300ms（数据量 ≤ 1 万条时）
- 界面参照主流后台管理风格（如 Ant Design），核心操作 ≤ 3 次点击

# 约束条件
- 技术栈：前端 React + Ant Design，后端 Node.js（Express），数据库 SQLite
- 单机部署，Windows 环境
- 3 天内完成 MVP

# 边界与异常处理
- Excel 中电话/邮箱格式非法：跳过该行，在导入报告中列出原因
- 重复客户（同名同电话）：合并为一条并提示
- 数据量超过 1 万条：给出分页与索引优化说明

# 禁止事项
- 不要引入超出 MVP 范围的功能（权限系统、多租户、消息通知）
- 不要使用需付费授权的第三方组件

# 验收标准
- [ ] 客户增删改查可用，数据刷新一致
- [ ] 订单可与客户关联并展示
- [ ] 导入 1000 条测试数据无丢失，非法数据有报告
- [ ] 1 万条数据下检索与列表响应 < 300ms

# 交互约定
- 设计阶段如有歧义，先与我确认，不要擅自决定
- 每完成一步汇报进度，允许我调整优先级
```

## 设计说明

- **角色 + 背景**：让 AI 具备专业视角和完整上下文，替代"帮我做个系统"的裸指令
- **任务拆三步（先设计后编码）**：把最大的返工风险（方向错误）前置消灭
- **质量量化**："好用"→ 具体指标；"功能全"→ 枚举 + 优先级
- **边界 + 禁止**：防止范围蔓延，异常路径有约定
- **交互约定**：遇到歧义先问，是降低反复修改成本的关键一条

## 问题类场景：同样需要打磨

用户的"提问"同样常因信息缺失而低效，打磨要点：

| 原问题 | 打磨后 |
|---|---|
| "为什么我的代码报错？" | 附完整报错信息、相关代码、环境（版本/系统）、期望行为 vs 实际行为、已尝试的方案 |
| "这个需求怎么做？" | 明确：受众、约束、偏好方案、期望产出（方案文档 / 对比分析 / 可执行计划） |

打磨问题的原则与任务相同：**让 AI 不靠猜，靠你给的完整信息作答。**
