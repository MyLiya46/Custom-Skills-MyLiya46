# Conventional Commits 规范（repo-committer 精要版）

本 skill 采用 Conventional Commits 规范，做如下截取与本地化约定。

## 规范格式

```
<type>(<scope>): <主题>

<可选正文：说明为什么改>
```

- `type` 必填，限定为以下 10 类之一。
- `scope` 可选，聚焦本工程的模块名（如 `api`、`chat`）。省略时连同括号一起省略。
- `主题` 用配置语言（skill config 的 `commit_message_language`，`"zh"` 中文默认 / `"en"` 英文）、动词开头、≤50 字，一句话说清「做了什么」。
- `正文` 可选：与主题之间空一行，用于说明「为什么改」、动机与影响，非「做了什么」的复述。

## type 枚举

| type     | 含义 | 示例 |
|----------|------|------|
| `feat`   | 新增功能 | `feat(api): 新增销售预测模型接口` |
| `fix`    | 修复缺陷 | `fix(chat): 修复长连接断流后不重连` |
| `docs`   | 文档变更 | `docs: 补充 README 快速开始` |
| `refactor` | 重构（不改变外部行为） | `refactor(auth): 抽离 token 校验为独立中间件` |
| `perf`   | 性能优化 | `perf(query): 为订单列表增加索引` |
| `test`   | 测试相关 | `test(api): 补充预测接口单元测试` |
| `chore`  | 杂项（构建/依赖/工具链之外的琐事） | `chore: 更新 .gitignore` |
| `style`  | 代码风格、格式化（不影响逻辑） | `style: 统一缩进为 4 空格` |
| `build`  | 构建系统或外部依赖 | `build: 升级 requests 到 2.31` |
| `ci`     | CI 配置 | `ci: 新增提交前 lint 检查` |

## 主题撰写要点

- 动词开头：`新增 / 修复 / 补充 / 抽离 / 升级 / 移除 / 调整 / 重命名` 等。
- 一句话、无虚词、无主观评价。
- 不写「为什么」「做了多少」的模糊话术。

## 反例（不得出现）

| 反例 | 问题 |
|------|------|
| `update` | 不是合法 type，也未说明对象 |
| `优化了一下` | 动词含糊，「一下」无信息量 |
| `改点东西` | 无对象、无意图 |
| `fix` | 纯 fix 无对象，不知道修了什么 |

## 为什么规范

- commit message 可被工具解析（changelog、语义化版本、回归定位）。
- 一条可读的历史，胜过一堆「update」。
- 强制书写者在提交前想清楚「这一次到底做了一件什么事」——这正好与原子化提交互为表里。
